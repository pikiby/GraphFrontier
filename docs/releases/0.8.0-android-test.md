# Android Runtime Test: 0.8.0

Tested on 2026-10-15 in the Android 15 API 35 x86_64 emulator (Pixel 5),
with Obsidian 1.14.4. GraphFrontier 0.8.0 was installed and enabled through
the actual Community Plugins catalog in a new app-storage vault named
`GraphFrontier Android Test`. Only synthetic notes were used.

## Confirmed

- Catalog installation, plugin activation and graph opening succeeded.
- Real touch input moved the camera and a pinned node. Two-touch input changed
  zoom from 1 to approximately 1.937.
- Long press opened the node context menu; Visual settings opened its controls.
- In-process plugin API checks passed for typed tag search, blacklist,
  whitelist, group colors, individual node color/aura, grid pinning, gravity
  node creation and linked-node selection. These do not prove every equivalent
  mobile UI interaction works.
- Copy linked names returned comma-separated lines and reported clipboard
  success; Android displayed its clipboard notification.
- An SVG attachment appeared after metadata refresh.
- Layout creation and loading restored saved settings instead of unsaved
  changes with autosave disabled. Manual save/load restored moved coordinates.
- With autosave enabled, the saved layout contained Backend coordinates
  x=120, y=80. After force-stopping and restarting Obsidian, the active layout,
  coordinates and graph (six nodes, three edges) were restored.
- Export through the API wrote a two-node, one-edge HTML graph inside the vault.
  Loading that HTML in an isolated WebView iframe initialized its canvas and
  interactive export interface. An absolute external export path was rejected.
- Rotation preserved the graph. Disabling/re-enabling the plugin and reopening
  the graph succeeded.
- On Android the API reported desktop=false and the MCP server was not running.

## Original 0.8.0 Failure: Bottom Controls Outside Viewport

With the side panel open in portrait orientation, scroll it to the bottom.
Save layout, Load layout and Export to remain outside the visible viewport.

Measured CSS pixels:

- Viewport: 393 x 851.
- Canvas: top 101.45, height 851.27, bottom 952.73.
- Side panel: top 109.45, bottom 944.73.
- Panel scrollTop 666.91, clientHeight 834, scrollHeight 1501: already at the end.
- Save layout: top 858.07; Load layout: 886.07; Export to: 914.07.

Repeated touch scrolling did not expose these buttons. In landscape, the
viewport height was 393 while canvas/panel bottoms were 469.09/461.09.
The original graph host used the full parent height without subtracting the
header; floating mobile navigation also overlapped the view. Local candidate
fixes use the available flex height and bound the graph by the visual viewport
and navigation. Subsequent emulator checks confirmed all three buttons were
hit-testable in portrait and landscape. The failure above is historical, not
an open blocker for the candidate.

## Physical Android And Candidate Checks

A Xiaomi M2003J15SC running Android 11 was tested with Obsidian 1.14.4 in a
separate synthetic vault. Local runtime assets were installed; this was not a
second catalog-installation test. Internal API checks covered tag search,
blacklist, layout save/load and unsaved-position rollback, autosave, attachment
orbit assignment, gravity-node creation and HTML export. The user confirmed
node long-press and background long-press after the fix. Automated Android
input injection was restricted by the phone; API success is not proof of all
keyboard or gesture flows. MCP itself was not tested on Android and remains
desktop-only.

Shared control styles and the compact color dialog were visually checked in
the emulator. The user accepted the improved appearance. Later validation and
stale-layout protection have additional regression tests; candidate publication
and installation of the published candidate remain separate gates.

## Synthetic Load Test

1000 generated Markdown files produced 1005 graph nodes and 2957 links, including
existing synthetic fixtures and a gravity center. Save/load times for the
1000-file stage were approximately 185/485 ms. Twelve generated files were
verified as zero-byte files; the cause is unresolved. Consequently, tag search
matched 988 files. This is not evidence of a matcher bug or proven plugin data
loss, and the fixture was not a fully populated 1000-note dataset.

A controlled comparison used the same programmatic camera path, without extra
render calls. Each sample lasted four seconds:

| State                            | Mean frame interval | Mean physics step | Mean draw call |
| -------------------------------- | ------------------: | ----------------: | -------------: |
| Settled, idle                    |             16.7 ms |           0.02 ms |        5.94 ms |
| Settled, moving camera           |             16.7 ms |          0.025 ms |        5.83 ms |
| Restarted physics, moving camera |             85.9 ms |           80.7 ms |        3.45 ms |

875 nodes moved in the active-physics sample. These are requestAnimationFrame
intervals and JavaScript timings, not a GPU profiler or a universal FPS claim.
The user separately reported roughly ten seconds of settling after increasing
link strength, followed by smooth navigation.

## Coverage Limits

Not verified exhaustively: iOS, minimum Obsidian 1.4.0, every touch/keyboard flow,
all attachment/pinning combinations, backup/restore/delete, or standalone-browser
export previews on the physical phone. iOS is explicitly not a release blocker
for the owner at this stage, but must not be advertised as tested. Touch box
selection remains unsupported. No backup copies were created and personal
notes were not used as test fixtures.
