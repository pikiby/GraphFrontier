# GraphFrontier 0.9.0

Reworked physics and rendering, tabbed settings, richer link styling and more reliable
saved-layout restoration. Requires Obsidian **1.12.7** or later, unchanged.

## Physics And Performance

- Reworked spatial indexing and numeric force calculations, caching forces between pinned and sleeping nodes. Moving neighbors still contribute forces and can wake sleepers.
- Apply degree-based mass to the summed force, fixing self-propulsion and unwanted rotation of asymmetric free clusters without suppressing all graph motion.
- Run up to three physics steps per animation frame within a time budget; dragging stays at one step. Render and smooth the camera once per frame.
- Reuse prepared node/group/link styles across camera and physics movement, invalidating them when appearance inputs change.
- Request animation frames only while simulation, camera movement or visual effects need them. Settled views stop requesting frames; autosave uses separate quiet ticks and retries.

Performance still depends on graph size, enabled effects and device. These changes
reduce repeated work, not guarantee a particular frame rate or speedup.

## Tabbed Settings And Groups

- Keep Search first and Layout last, with **Groups**, **Display**, **Physics** and **Selection** tabs inside Settings. Left/Right arrows and Home/End switch tabs.
- Keep the selected tab as a UI preference, separate from named layouts and backup payloads. Local GraphFrontier retains its own UI state and still starts with the sidebar closed.
- Use a group's eye icon to hide its matches. **Exclude** (default) removes them from drawing and physics; **Hide** removes them from drawing and interaction but keeps their physical influence. With subgraphs, hidden groups are always excluded.
- Alt-click an eye to solo that group; Alt-click it again to restore the previous hidden set. This restore history lasts until the view reloads; a plain click exits solo mode.
- Hidden nodes stay out of search, HTML export and API visibility in both modes. Physics-subset changes resume settling while preserving unaffected sleepers; returning nodes can react immediately.

## Visuals And Link Styling

- **Node size** is proportional across degrees, without the old radius ceiling, with a 0.1-2 scale. On-screen radius follows the square root of zoom; hit testing and labels follow the same geometry.
- **Link width** is 0.1-5 physical screen pixels, independent of zoom. Regular and painted links share width controls; the separate painted-width setting is removed.
- Set link color, opacity, **Show arrows** and **Reverse arrows** globally, by group or per node. Individual overrides beat groups, then global settings. Equal-priority endpoint conflicts prefer the stored source; width keeps the maximum-endpoint rule. Explicit false overrides inherited true.
- Arrows follow reference direction; reciprocal references show two heads but retain one physical spring. Reversal changes visuals only, not note links or physics.
- Highlighted links thicken relative to their own width and become fully opaque. **Hover color** optionally controls their highlight color and the hover ring. Links sharing an appearance are stroked together so translucency does not stack at crossings within that stroke.
- **Dim low-degree nodes** optionally draws established degree-0/1 nodes at 65% opacity, with highlights fully visible. Screen filters do not redefine this degree.
- **Strong pull x** supports 1-20 in shared node/group settings. An individual multiplier of 1 explicitly overrides a stronger group; clearing it restores inheritance. Resetting visual settings preserves force settings.
- Add an optional custom background, grid color and grid opacity. **Grid thickness** spans 0.1-2 CSS pixels, independent of zoom. Thin strokes fade instead of breaking into dashes. Applicable appearance settings also carry into static HTML exports.

## Navigation

- YAML `url` and `path` properties accept strings or lists of strings. Use quoted Markdown aliases such as `'[Dashboard](https://example.com/dashboard)'` for readable labels.
- **Open URL** and **Open path** always show destination submenus, even for one target, preserving aliases. Full targets appear in tooltips; empty or invalid list entries are ignored.
- URLs require HTTP(S). Paths support vault files, desktop external files/folders and `obsidian://open?...` links; arbitrary external-file navigation remains desktop-only.
- Plugin settings **Navigation** explains the syntax and offers **Copy example** without editing a note. API quick-open accepts one valid target and refuses ambiguous multi-target lists instead of silently choosing the first.

## Layout Restoration And Persistence

- Preserve proven settled sleep state with saved layouts and restore it only when the graph, positions, forces and constraints still match. A manual save that stops moving nodes does not falsely mark them settled.
- Wait for complete graph metadata before initial simulation or autosave, including metadata resolved during startup. Topology-neutral passive refreshes preserve equilibrium instead of needlessly restarting physics.
- Preserve exact, grid and orbit constraints when nodes return after filtering. Hidden pinned nodes keep their grid cells; dragging onto an occupied hidden cell shows its holder, then uses the nearest free cell. API move/pin results report `GRID_CELL_HELD_BY_HIDDEN_NODE` warnings.
- Keep the current Settings tab through layout loads and backup restoration without storing it in those payloads. Resume scheduled work after restoration guards clear.

## Upgrading And Compatibility

Existing data and layouts receive a **one-time node-size/link-width migration** to
`render_model: 2` when loaded. Unopened layout files migrate on their next load.
Node-size conversion preserves the former unlinked-node appearance within the new
0.1-2 range, but **high-degree nodes can look larger** because their radius is no
longer capped. Link widths convert from CSS pixels to physical pixels using the
pixel ratio of the first device that opens the graph, clamped to 0.1-5. Original
values and that ratio are retained in `legacy_render_settings`.

User-facing wording now says **links**. Existing API fields and identifiers,
including `edge_*`, `edges` and legacy painting commands, remain compatible; the
removed separate painted-width setting is not retained as an independent control.

Node lists, move/pin undo and automatic backups were introduced in
[0.8.9](0.8.9.md); they are not new features of this release.

Graph functionality supports desktop and mobile; Local MCP and arbitrary external-file
navigation remain desktop-only. This release does not establish new iOS verification.
