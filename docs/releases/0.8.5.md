# GraphFrontier 0.8.5: MCP Validation Without Runtime Code Generation

Changes since 0.8.4.

## Real Validation Without AJV In The Bundle

The MCP server now explicitly selects the SDK's CfWorker JSON Schema validator,
backed by the pinned `@cfworker/json-schema` 4.1.1 implementation. A narrow build
adapter also redirects the SDK's unconditional default AJV-provider import to
that real validator, so AJV and its runtime compiler are excluded from the plugin
bundle. Validation remains enabled; the adapter is not a no-op.

Tool inputs continue to use Zod. A shared bootstrap enables `jitless` before
application schemas or the MCP SDK are loaded. Guarded build transforms remove
Zod's dynamic-code probe and the generators in `core/doc` and `core/compile`,
covering both CommonJS and ESM dependency sources.

The interpreted parser remains intact: `z.compile(schema)` falls back to normal
validation, while strict compilation reports a typed unsupported error. No global
`Function` override or manual `node_modules` patch is used.

## Guarded Builds And Artifact Tests

Production and bundle tests use the same build-options helper. Adaptations are
restricted to reviewed Zod 4.6.7 and MCP SDK 1.32.1 sources, with pinned versions
and SHA-256 checks. A source or version mismatch stops the build and requires
review before the guards can be updated.

New artifact-level tests check the actual bundle for AJV packages and executable
dynamic-code references, including aliases. They exercise real JSON Schema and
Zod validation with string code generation disabled, verify compiler fallback
and strict errors, and check that changed upstream sources are rejected. Bundle
tests also cover mobile startup and the authenticated desktop MCP protocol in a
code-generation-restricted VM.

These checks are regression evidence, not confirmation that Obsidian's plugin
scan has cleared or that every device and workflow has been verified.

## Three Release Assets

The release publishes exactly three plugin assets: `main.js`, `manifest.json`
and `styles.css`. Manual installation uses those three files directly in
`<vault>/.obsidian/plugins/graphfrontier/`; there is no manual-install ZIP asset.
When updating, preserve your existing `data.json`, `layouts/` and optional
`mcp.json` rather than replacing the entire plugin directory.

Requires Obsidian 1.12.7 or newer. No physics or layout-format changes. Existing
layouts and the vault-relative HTML export workflow remain supported.
