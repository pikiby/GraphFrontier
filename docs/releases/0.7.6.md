# GraphFrontier 0.7.6

Gravity nodes, individual styling, color auras, and equilibrium-based motion settling.

This release describes changes since **0.7.5**.

## New: Gravity Nodes

Create an attraction center by right-clicking empty graph space and choosing **Create gravity node**.

- Give the center a name, configure attraction strength from 0 to 100, and add one or more rules.
- Use the existing search query types: `name:`, `path:`, `file:`, `tag:`, `line:`, `section:`, and `[property]:`.
- A note matching any rule is eligible for attraction. Multiple centers combine their influence.
- Drag a center to reposition it; click it or use its context menu to edit it.
- The compact editor reuses sidebar and query-dropdown styling. Enter keeps the typed rule; Tab or a suggestion click accepts a suggestion.
- Centers are graph objects, not Markdown files. Creating or deleting one does not create or delete a note.
- Rules, strength and positions are saved with the active layout.
- Pins, orbit pins, active drags and attachment isolation remain respected. Filtered-out notes do not participate in physics.
- Matching is cached, so moving a center does not repeatedly parse its rules.
- Gravity-node menus omit inapplicable controls such as Strong pull, edge painting and edge widths.

## New: Individual Visual Settings

Customize a node through its **Visual settings** submenu without changing the whole graph.

- Override node size, node color, regular and painted edge widths, Text zoom, text size and hover dimming.
- Attachment nodes additionally support their own attachment-size multiplier.
- Unset overrides inherit the main settings. One **Reset visual settings** action clears the node's visual overrides and edge painting, without resetting its pins or force multipliers.
- The color selector uses a compact circular swatch matching Groups.
- Changes follow layout Save, Load and autosave. Visual edits do not restart the physics simulation.
- Shared-edge widths prefer explicit endpoint overrides; when both endpoints override a width, the larger value wins.

## New: Color Auras

Individual visual settings now include **Color aura** and **Aura brightness**.

- A soft radial gradient extends around a node using its resolved color.
- Aura size defaults to zero, so auras are disabled until configured.
- The size control ranges from 0 to 5000, corresponding to a radius of 0 to 500 graph units.
- Brightness ranges from 0 to 50%, with a default of 22%.
- Auras render behind nodes and edges, respect visibility filtering, and do not change physics or mouse hit areas.
- These controls are intentionally absent from the main settings panel.

## Changed: Global Appearance

- Added a base **Node color** setting. Individual node colors override Groups; Groups override the base color.
- Increased the maximum node-size scale from x2 to x4, including the rendering limit.
- Extended **Text zoom** from 20 to 40 steps in both global and individual settings. These are zoom steps, not a linear distance scale.

## Fixed: Motion Stopping Too Early

Previously, the simulation applied an additional time-dependent brake and stopped three seconds after a layout action, even when nodes were still being pulled toward another position. Repeated dragging could therefore be needed to continue arranging the graph.

- Removed that timed brake and the unconditional three-second stop.
- Kept the normal Damping setting for velocity decay.
- Nodes sleep after eight consecutive frames of low speed and low net force.
- A higher wake threshold prevents small force fluctuations from repeatedly waking settled nodes.
- Physics pauses when all movable nodes are asleep. Layout-changing actions reactivate it.
- Autosave still waits for stillness and respects its existing guards.

This is equilibrium-based settling, not a guarantee that every competing-force configuration converges. Live behavior on large user graphs still needs evaluation.

## Improved: Search And Node Actions

- The main Search row starts with `name:` and keeps an explicit query type instead of exposing an untyped input state.
- Clearing the query retains its type. A prefix without a value does not count as a filled search.
- Query types remain selectable through the existing dropdown.
- Added **Copy name** to the node's Copy submenu.
- A note's `path` property can now open an `obsidian://open?...` URI, including a link to another vault. The host handles the destination and window behavior.
- The `url` property remains restricted to HTTP/HTTPS; Obsidian URIs are recognized only in `path`.

## Improved: Static HTML Export

Standalone exports now carry node colors, auras, individual node radii, Text zoom thresholds, text sizes, hover-dimming overrides and edge widths. Exported graphs retain fixed positions with pan, zoom and note previews; they do not run physics.

## Compatibility And Validation

- Existing layouts remain loadable. New optional fields default to inherited visual settings and disabled auras.
- Legacy text-size storage and internal gravity-node identifiers are retained for compatibility.
- Sidebar collapse state remains independent of layouts.
- The minimum declared Obsidian version remains 1.4.0.
- Local validation: 204 automated tests, Prettier, ESLint, production build and exact-version release checks.
- The existing restriction on saving while search has query content has not been removed.
- This release does not claim to fix hidden-folder indexing or the previously reported blacklist suggestion-acceptance behavior.
- HTML exports can contain note text. Review their contents before sharing.
