# GraphFrontier 0.8.0

## Your Graph, Now Programmable

GraphFrontier 0.8.0 adds a JavaScript graph API and an embedded MCP server with
**32 tools**. Connected agents can work with the same graph you see: inspect
relationships, change appearance and physics, build a focused layout, protect
saved versions with backups and export a standalone diagram.

This release covers changes since **0.7.7**. Gravity-node repulsion, mobile HTML
export and mobile-safe navigation were already released in 0.7.7; they remain
available and are not counted as new features here.

## New: Embedded MCP Server

- Enable the optional server in **Settings -> GraphFrontier -> Local MCP**. It is off by default and available on desktop only.
- Connect through Streamable HTTP at `http://127.0.0.1:27125/mcp`, using the generated Bearer token. The port is configurable; use different ports for different vaults.
- Setup examples are included for Codex, Claude Code and OpenCode 1.x. Use a client that supports the SDK's negotiated MCP revisions; localhost HTTP is not accessible from every cloud or desktop connector.
- The server is part of the plugin. There is no separate GraphFrontier daemon, bridge, npm install or Node installation for users.
- The listener starts with the enabled plugin, independently of graph tabs. It stops when MCP/the plugin is disabled or Obsidian closes. An agent can explicitly open a graph tab when needed.
- Dependencies are bundled in `main.js`. The desktop host must provide Node 18+ and Web Fetch APIs. If MCP cannot start, the graph remains usable. Mobile does not load the server or its Node modules.
- MCP settings and credentials live in a separate `mcp.json`; selecting or restoring a layout never replaces the server token or port.

## New: Graph API Capabilities

### Inspect And Understand The Graph

`list_views`, `get_state`, `get_graph`, `get_selection`, `get_configuration` and
`get_node_settings` expose vault identity, open tabs, layout state, camera,
paginated nodes/edges, explicit selection, global settings, rules and effective
per-node settings. Graph inspection returns metadata, not full note contents.

Clients use explicit view IDs and context tokens. A layout switch or graph
rebuild invalidates old tokens, preventing a queued action from silently
targeting a different graph state. Paginated reads can use the same token to
detect changes between pages.

### Search, Highlight And Filter

- `search_nodes` searches without changing the UI. It uses existing typed queries: `name:`, `path:`, `file:`, `tag:`, `line:`, `section:` and `[property]:`.
- `set_search` controls the existing Find/Filter mode, query and linked highlighting.
- `highlight_nodes` highlights explicit IDs, optionally including their neighbors, without requiring a shared query.
- `select_nodes` replaces or clears the explicit selection; `frame_nodes` fits the camera to visible IDs without moving nodes.
- `set_visible_nodes` restricts the graph to an exact set and its internal edges. This extra filter intersects normal visibility rules and is saved with the layout; `null` clears it.
- `edit_rules` adds, updates, enables/disables, removes, reorders or clears Groups, Blacklist and Whitelist rules. Groups retain their existing color priority.

### Style And Arrange Nodes

- `update_settings` patches all current global settings, including physics, display, attachment behavior, autosave and interaction modifiers.
- `update_node_settings` changes individual sizes, colors, labels, edge widths, painted edges, hover dimming, aura radius/brightness and force multipliers. Remove an override to restore inheritance, or reset visual overrides together.
- Visual fields use the shared UI settings catalog and limits. Unsupported fields and invalid values are rejected rather than silently clamped. Gravity nodes still exclude edge settings and Strong pull.
- `move_nodes` assigns coordinates while preserving pin modes unless a different mode is requested.
- `pin_nodes` supports exact/grid pinning and unpinning for explicit or all nodes, plus linked-node/attachment actions including orbits. Linked actions operate on direct neighbors; the anchor can be pinned separately.
- `set_camera` sets position/zoom or fits visible nodes. `graph_action` opens/refreshes a graph, pauses/resumes physics, aligns pins, selects linked nodes, arms box selection or clears selection.
- `gravity_nodes` creates, edits and removes gravity centers with names, typed queries, coordinates, attraction and repulsion.
- `update_ui` controls panel visibility, collapsed sections and built-in command hotkeys.
- `node_action` copies a node's name, vault/system path, Obsidian URL or linked names/paths; opens supported notes/destinations/local graphs; and shows or closes previews. Copy actions return text and optionally update the clipboard.

### Manage Layouts And Recover Saved Versions

`list_layouts`, `create_layout`, `save_layout`, `load_layout` and `delete_layout`
let an agent manage layouts without editing their JSON directly. A new layout
can copy current unsaved graph state or an existing saved file, then optionally
become active. Creating a layout never overwrites an existing name.

`backup_layout`, `list_backups` and `restore_layout` add explicit recovery tools:

- Backups live in `layouts/backups/`, separate from selectable layouts, and preserve the original saved JSON text with its name and timestamp.
- `ensure: true` reuses an identical backup instead of creating duplicates. Changed saved content receives a new backup.
- MCP save, delete and replacement during restore create/verify a backup of the existing destination first. A failed backup blocks the destructive step.
- Restores can target the original layout or a new name. Restoring over the active layout reloads the restored state, preventing old in-memory state from immediately overwriting it through autosave.
- A valid backup can recover a damaged destination; the damaged bytes are preserved separately first. Backup listings distinguish valid layouts from non-restorable forensic copies.
- Deleting the last layout is rejected. Before deleting an active layout, the fallback must be readable.
- MCP writes are serialized, and layout operations share the existing save/load queue. Backups are not silently removed.

Backups capture saved files, not unsaved edits. Switching layouts still discards
unsaved edits as in the UI. Local backups protect against logical replacement
and deletion, not disk failure. Autosave remains an explicit layout setting.

### Export A Focused Diagram

`get_export_locations` discovers the vault, home and desktop locations when
available. `export_html` writes the existing interactive static graph format:
fixed node positions, camera pan/zoom, hover and optional Markdown previews.

- Export current visibility or pass exact node IDs. Explicit exports include only those nodes and edges with both endpoints included.
- Set `includeContents: false` to omit note previews; paths and other metadata can still be included. Previews remain enabled by default.
- Existing files are not overwritten unless `overwrite: true` is supplied. MCP exports leave the UI's remembered export destination unchanged.
- The result reports the actual output path and node/edge counts. If the desktop cannot be resolved, the client can ask for a path instead of guessing.

For example, a connected agent can handle: "Create an Architecture layout, show
only notes tagged backend and their direct neighbors, pin them to the grid,
color the entry points yellow, save it and export the diagram to my desktop
without note text."

## Improved: Layout Snapshots And Persistence

- Newly captured layouts include camera position/zoom, the search query and an exact API node subset, in addition to existing positions, settings, pins, colors and gravity centers.
- Saved camera state survives loading a layout and reopening the graph. Older layouts without the new camera marker keep their existing opening behavior.
- MCP saves can capture a filled search field. The manual UI Save button and normal autosave retain their existing nonempty-search restriction.
- Collapsed menu sections remain global UI preferences, not layout-owned settings.
- Layout deletion and switching now use the shared file-operation queue, including fallback validation before active-file deletion.
- Attachment link distance `1` now survives save/load correctly instead of being mistaken for an old fractional multiplier.

## Fixed: Pinning Must Not Remove Influence

Pinned nodes were excluded from repulsion whenever either member of a pair was
fixed. Additional orphan and attachment-anchor calculations also omitted them.

Exact, grid and orbit pinning now retain the node's repulsion toward eligible
free nodes while preserving the positional constraint. Two fixed nodes remain
fixed. Existing link attraction and Strong pull toward free linked nodes are
preserved, as are force coefficients and attachment-isolation rules.

## Security, Scope And Known Limits

- The listener is loopback-only, requires a token, validates Host/Origin, and limits request size, concurrency, rate and time. It does not expose a LAN endpoint or cloud tunnel.
- Possession of the token grants graph read/write capabilities, including layout deletion and explicit exports. Connect trusted clients and use their approval controls. Keep `mcp.json` private.
- GraphFrontier does not send data to an AI provider itself. A connected client may send tool results to its model provider; local transport alone does not guarantee local processing.
- Blacklist and Whitelist are visual filters, not access controls. Authorized clients can request hidden metadata or operate on explicit hidden IDs where supported.
- There is no arbitrary JavaScript execution, generic note editor, vault-file deletion, or native/third-party menu callback access such as merging or bookmarking. Server credentials and enable/port controls are not exposed as graph tools.
- Node IDs are vault-relative paths. Automatic matching of system paths to linked external files is not implemented; clients must verify candidate nodes through `copy_system_path`.
- Explicit node batches are generally limited to 500; large reads use pagination. Positions remain live during physics, not frozen across pages.
- The graph remains mobile-capable. MCP is desktop-only, and physical Android/iOS validation of the existing mobile functionality is still pending.

## Validation And Updating

The release suite contains **305 automated tests**, including 47 added for pin
influence and isolation behavior. Coverage includes real SDK HTTP handshakes,
tool discovery/calls, authentication rejection, state checks, layout round trips,
backups/restores, generated HTML execution and desktop/mobile bundle loading.
Runtime dependency audit found no known vulnerabilities at release preparation.

Install by replacing the plugin's runtime files, preserving `data.json`,
`layouts/` and `mcp.json`, then reload GraphFrontier. MCP remains disabled until
enabled in local settings. No note migration or additional server installation
is required. The plugin minimum Obsidian version remains 1.4.0; the optional MCP
server has the newer embedded-runtime requirement described above.
