# GraphFrontier 0.7.7

Gravity-node repulsion and mobile-safe export and navigation.

This release describes changes since **0.7.6**.

## New: Repulsion For Gravity Nodes

Gravity centers can now attract matching notes while pushing nonmatching notes away.

- The compact gravity editor includes a **Repulsion** slider beside **Attraction**, using the same styling and a 0-100 range.
- Repulsion defaults to **0 (off)**, including when loading older layouts. No separate toggle is needed.
- Matching any of the center's existing query rules makes a note eligible for attraction, not repulsion from that center. No additional filter syntax is introduced.
- Repulsion decreases smoothly with distance and reaches zero at **1000 graph units**. Its strength was reduced to one quarter of the initial local prototype during testing.
- Each center evaluates membership independently: a note attracted by one center may be repelled by another whose rules it does not match.
- Gravity centers do not repel each other. Pinned, orbit-pinned, actively dragged and hidden notes remain protected by the existing physics rules; attachment isolation still applies.
- Repulsion works even when Attraction is zero. A deterministic separation direction handles notes exactly at the center.
- Query matching stays cached across movement. Moving a center does not reparse its rules every frame.
- Repulsion is stored with the active layout and follows the existing Save, Load and autosave behavior.
- Aura size remains a visual setting and does not control repulsion distance.

## New: Mobile Static HTML Export

- On mobile, **Export to** accepts a vault-relative path such as `Exports/graph.html` and writes through Obsidian's public Vault API rather than Node.js filesystem APIs.
- Missing folders are created. An existing target HTML file is overwritten; an existing folder or a path ending in `/` uses `graphfrontier-static.html` inside that folder.
- Absolute paths, URLs, parent traversal, hidden folders and invalid filename characters are rejected by mobile export.
- Desktop export retains its absolute-filesystem-path behavior.
- Desktop and mobile export paths are remembered separately, only after a successful write. The first-use field remains empty.
- Both platforms use the same standalone graph renderer, with fixed node positions, pan, zoom, hover and note previews.

## Improved: Mobile Navigation

- Mobile URL and Obsidian URI navigation no longer attempts to use Electron, even if a host exposes a `require` function.
- Vault files open through Obsidian. Arbitrary external files and folders remain desktop-only, with a notice for unsupported paths.
- Obsidian URIs remain recognized through the note's `path` property; the `url` property remains limited to HTTP/HTTPS.

## Compatibility And Validation

- Existing layouts remain loadable; omitted Repulsion values normalize to zero.
- No migration of notes or saved layouts is required. The declared minimum Obsidian version remains 1.4.0.
- Automated coverage includes repulsion membership and falloff, pin and drag exclusions, layout persistence, mobile export paths and writes, navigation without Electron, and generated HTML execution.
- Mobile behavior has automated coverage using simulated platform and Vault APIs. Physical Android and iOS device validation is still pending.
- HTML exports can contain note text and metadata. Review their contents before sharing them.
