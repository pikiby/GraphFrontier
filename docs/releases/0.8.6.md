# GraphFrontier 0.8.6: Subgraphs And Additive Box Selection

Changes since 0.8.5.

## Named Subgraphs Without Changing Your Notes

Select existing nodes, then choose **Combine selected into subgraph** from a node
or background context menu. The compact dialog asks only for a **Name**; your
selection supplies the members. Subgraphs belong to the current layout. Creating,
renaming or removing a container never creates, edits or deletes notes, folders
or Markdown links.

The parent graph represents the selection as a hollow standard ball with a thicker
outer outline. Links from members to outside nodes are remapped to that container
and deduplicated. The container participates in the existing graph physics and
normal node controls: dragging, multiselection, exact/grid/orbit pinning, Strong
pull, colors, auras, sizes and edge appearance. Subgraphs can contain other
subgraph containers.

There is no in-place expand/collapse. Single-click selects the container;
double-click or **Open subgraph in pane** opens its contents in a separate
Obsidian pane, not an operating-system popout. Opening the same subgraph again
reveals its existing pane.

## Independent Inner Graphs

Each subgraph has its own local coordinates, camera, filters and physics. The
outer container is not an extra actor inside its own graph. Moving it in the
parent graph does not translate or rearrange its members, and closing the inner
pane does not expand or rearrange the parent graph.

On first opening, framing waits for a usable viewport, includes node radii and
adds padding. This initial inner fit can zoom in up to 2x so small graphs do not
start unnecessarily distant. A saved inner camera is restored on reopening
instead of being fitted again; main-graph framing is unchanged. **Graph settings**
starts hidden in a newly opened subgraph pane, with the existing **Show** button
available normally. Refreshing does not hide settings after you show them.

Whitelist, blacklist and exact-node filters continue to apply to members and
projected links. A matching member can keep its parent container visible, but
opening that container does not bypass those filters. Inner filter state is
saved separately. Gravity centers act only within their current graph scope.

## Rename, Ungroup And Save

Use **Rename subgraph** to change a container's name. **Ungroup subgraph** removes
only the container and releases its immediate members around the container's
**current position**, using their latest local offsets. A nested container moves
into the parent space without translating its own interior. Notes, their links
and member visual settings remain intact.

Saving from any pane gathers positions from the open graph spaces while retaining
closed and filtered members. Inner saves do not replace the main graph's camera
or search state. Exact and grid pins are converted between parent and local
coordinates while retaining their modes. Layout Save, Load and autosave continue
to govern persistence: with autosave off, grouping and other edits remain unsaved
until you explicitly save.

Subgraph creation and Ungroup wake the affected graph's physics immediately,
without requiring a first pointer event. Explicit saved-layout restoration
remains paused. Closing a scoped pane does not discard the parent's unsaved
changes. Panes whose scope no longer exists after Ungroup or a layout switch
remain empty rather than exposing the full graph. These are subgraph lifecycle
and persistence safeguards, not a general physics-engine overhaul.

## Add To A Selection With Shift

Hold **Shift** while box-selecting separate areas to accumulate a selection.
Each rectangle adds its nodes to the selection captured when that gesture began:
overlap does not toggle nodes off or add duplicates, and an empty rectangle
preserves the existing selection. Releasing Shift before finishing the gesture
still keeps that starting selection.

A configured box-selection modifier or armed box-selection command without Shift
continues to replace the selection. A normal click on empty graph space clears
it as before. Node selection toggles and dragging selected nodes are unchanged.

## MCP And Internal API

The new `subgraph_nodes` MCP tool and matching `subgraphNodes(args)` internal API
use the same layout operations as the UI:

| Action    | Behavior                                                              |
| --------- | --------------------------------------------------------------------- |
| `create`  | Create a named container from `memberIds` or the current selection.   |
| `rename`  | Change an existing container's name.                                  |
| `open`    | Open or reveal its separate pane, returning `openedView`.             |
| `ungroup` | Remove the container and release members around its current position. |

`get_graph` reports containers as `type: "subgraph"`; view state includes
`subgraphId` (null for the main graph), and configuration includes the layout's
subgraph definitions. Node movement and pin operations use coordinates local to
the targeted view. Mutations require the usual `viewId` and current
`contextToken`; reread state after grouping or Ungroup. These operations do not
enable MCP or change its existing authentication and desktop-only restrictions.

See the [tool reference](../mcp.md#tools-and-internal-api) and
[subgraph usage guide](../usage.md#subgraphs).

## Demonstrations And Current Limits

The README now includes subgraph and Open URL demonstrations. **Open URL is an
existing feature, not an addition in 0.8.6**: a note with a `url` string property
offers the context-menu action to open that address in the default browser.

- Membership is fixed after creation. To change it, Ungroup and create a new
  subgraph from the desired selection; there is no add/remove-members editor.
- Orbit pins remain orbit pins when member and anchor share a graph space. If
  grouping separates them, the member becomes an exact pin at its converted
  position instead of being pulled across independent graphs.
- Static HTML export shows the current projected graph and hollow containers;
  it does not provide subgraph editing or separate nested panes.
- The user confirmed the desktop workflow in actual use. This release has not
  received new phone or iOS verification; previous Android checks are not proof
  of subgraph behavior on mobile. Touch box selection remains unavailable.

Requires Obsidian **1.12.7** or newer. The release retains the existing three-file
manual installation: `main.js`, `manifest.json` and `styles.css`. When updating,
preserve your existing `data.json`, `layouts/` and optional `mcp.json` rather than
replacing the entire plugin directory.
