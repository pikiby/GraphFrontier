# GraphFrontier 0.8.4: Choose Your Export Destination

Changes since 0.8.3.

## Export Inside Your Vault

**Export to** and the static HTML export command now open a compact **Export
graph** dialog instead of immediately saving and replacing a fixed file.

- Choose a **Folder** inside the current vault, then a **Filename**. Existing
  folders appear as native suggestions; you can also type a new nested folder.
  Leave the folder empty to save in the vault root.
- The default filename is `graphfrontier-static.html`. The HTML extension is
  added when omitted, and missing parent folders are created during export.
- The dialog names the destination vault. Absolute paths, URLs, parent traversal,
  hidden folders and reserved names are rejected using the shared vault-path
  validation.

## Explicit Replacement And A Persistent Result

An existing destination changes the main button to **Replace file**. Replacement
requires that explicit action; a file appearing concurrently does not silently
turn an earlier **Export** action into permission to overwrite it.

Errors appear inline without clearing the entered folder or filename. Controls
are disabled while exporting to prevent duplicate submissions. Enter in the
folder field selects a suggestion rather than submitting an export.

After saving, the dialog stays open with **Saved** and the full vault-relative
output path. **Open file** opens that result through Obsidian's default-app
action. If opening is unavailable or fails, the saved path remains visible with
an inline error. Use **Close** to dismiss the result.

## Refreshed README And Demos

The README now shows a real MCP request and its saved **Twin Stars** layout, with
screenshots of the request and result. Updated GIF demonstrations cover gravity
nodes, repulsion, saved layouts, individual node visuals and HTML export.

These examples document existing gravity and API/MCP capabilities; they are not
new gravity or API features introduced in 0.8.4.

## Compatibility

Explicit-path API/MCP exports remain non-interactive and retain their
vault-relative path and explicit-overwrite contract. Storage continues to use
Obsidian's public Vault API on desktop and mobile; no filesystem or Electron
export picker is added. Filenames and folders are not remembered.

Exports can contain note text, paths and metadata. Review them before sharing.
HTML files may be hidden in Obsidian's file explorer; this release does not
change global visibility settings. Vault storage follows the adapter's behavior,
including linked folders; it is not a physical-path sandbox.

Requires Obsidian 1.12.7 or newer. No layout-format or physics changes.
